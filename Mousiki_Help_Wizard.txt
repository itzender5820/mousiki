OVERVIEW OF THE CAPABILITIES OF MOUSIKI PLUS: [[Header]]
Apart from playing and queuing local and online files, the Mousiki Plus
music player offers the possibility to create playlists, download online
files (YouTube, SoundCloud, Bandcamp), adjust and fetch meta data from
online sources (AcoustID/MetaBrainz), a synced lyric function (including
timing adjustment, lyrics translation and a Karaoke mode!), includes
various visualizations of your music (e.g. spectrogram, XY/YT-mode
oscilloscope), an equalizer / sound normalization, sleep timer, file
format conversion, a smart listening history, (custom) color themes
and then some...

The radio player mode includes a lot of the features of the regular
music player and lets you listen to a vast variety of online radio
channels that can be added via an online search mode or manually and
organized by creating stations lists. It includes a recording function
and a listening history that contains meta data, so you can search and
download songs you listened to on the radio. Channels can be assigned
preset keys to tune in to channels fast...

The audio book mode is the third mode: the music player shaped for
books (books and chapters instead of library and queue, an opening
book in place of the disk, tags made for books).

THE TERMINAL FONT: [[Header]]
The disk and the pictures are braille characters. They look full and round
with Cascadia Mono, the font Mousiki uses for its own window where the
terminal allows it (Settings, GENERAL, TEXT AND TRANSLITERATION,
Terminal Default Font switches that off). A font without braille characters shows small scattered dots.

2.1.1 THE MAIN MUSIC PLAYER UI AND ITS SCREEN PANES [[Header]]

MODE CHANGE:[[Header]] [SHIFT and +] (German keyboard) or ['] (English keyboard) switches to the
next mode, [SHIFT and -] (German) or [;] (English) to the previous one: music player, radio and
audio books, in the order of Settings -> GENERAL -> MODES (every mode can be switched off there).
Both keys can be changed in Settings -> REFERENCE (Next Mode / Previous Mode).

COVER LOOK:[[Header]] [CTRL+t] one look back, [CTRL+z] one forward: plain disk, Just Cover, Cover
with Gradient, Cover behind Disk, v2, Full Anima, Cover ASCII, Cover ASCII with Gradient. In the
audio book mode: default picture, cover with gradient wave, cover in its own colours. Only while
Eliment Disk / Cover is on; saved at once. Changeable in Settings -> REFERENCE. An album with
its own look (meta editor -> Style Option) changes that look instead.

MENUS INDEX:[[Header]] [<] (German keyboard) or [SHIFT+,] (English keyboard) lists all menus
and overlays with their keys; [ENTER] opens the selected one.

The main screen consists of five panes, which are discussed below. The focuse between the
SEARCH, LOCAL AUDIO FILES and QUEUE can be changed via [TAB], where the [◀] is an indicator
for the current focus. Commands that work no matter which pane is focused are [n] for next
song in list and [b] song before current song in a list (while a LOCKED queue has titles, in
any pane, [b] plays the previously played queue song), [p] play/pause, [+/-] change
volume, [x] mute, [SHIFT+n] to toggle if either the filename or the meta data track name
is shown in the track lists, as well as all commands that open certain overlays (such as
the settings, oscilloscope parameter overlay etc.).

MAIN PANE:[[Header]]
Includes the Mousiki disk, meta data information, visualizations and
lyrics (only music player mode). Several adjustments to this pane (e.g. turning visualizations
on/off) can be made in the settings "GENERAL" tab ([s] to open and save setting).

PROGRESS BAR: [[Header]]
Shows the progress of an audio file. Use [<-/->] to seek through a track (in steps of 5 s).

VOLUME, PLAY/PAUSE, PLAYEBACK MODES: [[Header_line]]
The volume can be changed via [+/-].
If a track shall be played or paused can be controlled via [p].
A track can be muted by using [x].
Playback modes such as e.g. R for repeat or S for shuffle can be changed via [m]. For more
details see PLAYBACK MODES[[Header]].

SEARCH BAR: [[Header]]
Type in a search query. See SEARCH[[HEADER]] and DOWNLOAD[[Header]] for details on what
can be specifically search for.

LOCAL AUDIO FILES: [[Header]]
When focused or using the search bar [UP]/[DOWN] can be used to hover through the track list.
[ENTER] starts a song and hitting [ENTER] again locks the current search result, so that only
the results are shown in the list. Hit [ESC] to clear a search result and the complete list
of local files will be shown again.

Hitting [a] adds a song on the top of a queue. See chapter on  BUILDING A QUEUE[[Header]] 
for more details.

Using [SHIFT+n] toggles between showing the filename / track name in the lists, [SHIFT+t]
changes the sorting of the local audio files: folder order, file name / title A-Z,
artist A-Z, recently added (newest files first), and - while the video mode is on - only
videos.

The command [f] filters the local list by folder, which means, when a highlighted track is
e.g. in folder with other tracks from the same album, it will then only show the files in
the associated folder. Use [c] or [ESC] to clear folder filter.
[SHIFT+l] opens a BIG LIST OVERLAY[[HEADER]] for a better overview.
[SHIFT+f] opens the BIG FOLDER OVERLAY[[Header]].
[SHIFT+k] opens the BIG QUEUE OVERLAY[[Header]].
In the big queue overlay [SHIFT+s] shuffles the order of the queue, [SHIFT+u] undoes the shuffle.
The three big overlays switch directly: with one open, press the key of another
([SHIFT+l], [SHIFT+k], [SHIFT+f]) - no need to close it first.

QUEUE PANE: [[Header]]
See BUILDING A QUEUE[[Header]] for details on how to e.g. adjust the queue order, how to
save a queue to a list and more...
The bottom border shows how many titles are below the visible rows: ( 5 more ).
[ENTER] plays the highlighted item; [SHIFT+ENTER] plays it AND moves the whole queue along to it (the
items in front of it go to the end in their order, as if they had been played).

2.1.2 MUSIC FILE PATHS [[Header]]

ADDING/CHANGING PATHS: [[Header]]

HOW TO GET TO THE SETTINGS PATH TAB: [[Header]]
[s]  Settings [[Legend]] ->>  PATHS [[Header]] ->>  LOCAL PATH [[Header]] to set several paths.
For more details on all the SETTINGS TABS see chapter SETTINGS AND COLOR THEMES[[Header]]. 

Move onto a row, press [ENTER], type in folder path, hit [ENTER] again to change/add a path. 
An empty line plus [ENTER] removes that path. Paths accept "~" and "%USERPROFILE%" and both 
slash directions on Windows.
Committing a change rescans the library at once. Note that the download folder is included in
the list automatically, so you do not have to add it as a local path manually.

RESCAN LIBRARY: [[Header]]
Can also be done at any time via the command [SHIFT+r] when adding/deleting files while
Mousiki is currently running (restarting also triggers a new scan). 

TAGS ARE KEPT BETWEEN RUNS: [[Header]]
The tags of the library (title, artist, album, year, length) are kept in ~/.cache/mousiki/tag_cache.txt.
At the next start every file whose size and modification time did not change gets its tags from there
at once, so search and sort work right away; only new and changed files are read again.

IMPORTANT BEFORE LEAVING THE SETTINGS: [[Header]]
Remember to leave the settings by hitting [s] to save changes (made in the config.txt). 
Exiting via [ESC] or [q] exits the settings and discards changes that were made, but you
will also see a warning message appear when you try to do so...

See the chapter on SETTINGS AND COLOR THEMES[[Header]] for details on all the paths that can be set.

2.1.2.1 SUPPORTED FORMATS[[HEADER]]

Supported are the usual formats, including some unusual ones.

REGULAR FORMATS: [[Header]]
MP3, FLAC, WAV, OGG, Opus, M4A and other common formats play out of the box.

=> See FFmpeg for a full list of supported formats! [[Legend]]

Apart from that a variety of retro formats, which show up in the list below
are also supported and behave like any other track in search and the queue.
The below needs FFmpeg built with libopenmpt and libgme. When installing
Mousiki Plus it will upgrade FFmpeg, however the upgraded version has to be
on top in PATHs list, in case other or older versions were installed in the
past.

Tracker modules (Amiga / PC demoscene):[[Header]]
  .mod .xm .it .s3m .mptm .stm .669 .mtm .med .okt .far
  .ult .ams .dbm .digi .dmf .dsm .gdm .imf .j2b .mdl .mt2
  .psm .ptm .umx .plm
=> the above need FFmpeg built with libopenmpt[[Legend]]

Game console music:[[Header]]
  .nsf .nsfe (NES) .spc (SNES) .gbs (Game Boy)
  .vgm .vgz (Sega) .ay .hes .kss .sap .gym
=> needs FFmpeg built with libgme[[Legend]]

Commodore 64 SID tunes:[[Header]]
  .sid .psid .rsid
=> needs sidplayfp on the PATH (https://github.com/libsidplayfp/sidplayfp)[[Legend]]

In the meta data field of the main UI the TYPE column says tracker module,
game music or C64 SID (n tunes), and the module's own title is used as its
metadata title. If a required tool is missing, the status line says which
one and the track is skipped.

A SID tune has no end, so it is rendered once for SidPlayLength seconds
with a default of 180s.

2.2.1 SEARCH AND FILTERING CAPABILITIES [[Header]]

DIFFERENT SEARCH CAPABILITIES:[[Header]]
[/]  open/focus the search bar. The prefix picks the source:

[/]    +  query       your local library      live, as you type
[/v:]  +  query       your video files        live (Video mode on)
[/s:]  +  query       YouTube                 live on [ENTER]
[/sc:] +  query       SoundCloud              live on [ENTER]
[/b:]  +  query       Bandcamp                live on [ENTER]
[/sv:] +  query       YouTube videos          live on [ENTER] (SEARCH YT)
[/p:]  +  query       your saved playlists    live
[/f:]  +  query       your folders            live

The local search is fuzzy: "X Files" also finds "X-Files". It also looks at the Latin spelling of Japanese,
Korean and Chinese titles: "sakura" finds さくら. The radio's station search does the same.

TRANSLITERATION TAKEN INTO ACCOUNT:[[Header]] [SHIFT+'] on a US keyboard (the key is ["], 
German [SHIFT+2]) shows Japanese kana, Korean and Chinese text in Latin letters: titles, 
tags, file names, lyrics, karaoke, READ LYRICS (it also works inside karaoke and READ LYRICS). 
Transliteration is taken into account for the search, but does not apply to searches for the
Radio station browser or other online searches.

RADIO:[[Header]] The radio mode has the same key: station names, the title that plays now, the lists and the
menus switch too (the setting is shared with the music player).

GENERAL:[[HEADER]]
[UP] / [DOWN] while typing, then [ENTER] plays the highlighted result
right away
[ENTER] without moving keeps the search as the filter
[ESC] cancel and restore the unfiltered list view

NOTES ON SEARCH BEHAVIOR: [[HEADER]]
On a playlist row (/p:) [ENTER] queues all of its tracks.
On a folder row (/f:) [ENTER] opens that folder in the list, like [f].
Online searches only run on [ENTER], never per keystroke.
SoundCloud's 30-second previews and unplayable tracks are left out of
the results, which is why it takes a few seconds longer to search...

2.2.2 DOWNLOAD (MUSIC PLAYER) [[Header]]

SAVING WHAT YOU STREAM:[[Header]]
[y] saves the streamed track that is playing right now

SAVE FORMATS: [[Header]]
YouTube    =>  Opus
SoundCloud =>  MP3 / Opus / AAC, as the site sends it
Bandcamp   =>  the free 128 kbit/s MP3 stream

The file is named Title - Artist.ext, the cached copy is
removed, and the library refreshes so it appears as a local
track straight away.

DOWNLOAD LOCATION:[[HEADER]]
Set download PATH at [s] Settings[[Header]]  ->>  PATHS[[LEGEND]]  ->>  DOWNLOAD PATH [[Header]]
Default download path is inside the cache folder (~/.cache/mousiki).
The download folder is scanned automatically, so you never have to repeat it as a
local path. The radio puts its recordings in the same folder by default.

SHARED DOWNLOAD HISTORY OF MOUSIKI AND YT-DLP:[[Header]]
When using yt-dlp it places a downloaded_history.txt file inside the chosen download path. This
can lead to the case that the history file is accidentally moved and when e.g. downloading a playlist
to which you may have added new files, it will not download the new files only, but all of them again.
To avoid this the history is placed inside a folder called "history" which is placed within the
download path that was chosen in the setting. Mousiki avoids duplicates by checking for files with
the same file name and therefore does not rely on the history itself, but is built to add lines
to the history file that is created by yt-dlp using it outside Mousiki so duplicates are avoided.
When using yt-dlp outside of Mousiki it is recommended to point the history file to the same folder
Mousiki is creating inside the chosen download path as seen below (maybe create a shell profile
function for downloading songs and playlists from it). NOTE: When the download folder is changed in
Mousiki, the history folder will be copied (not moved!) to avoid history amnesia on the yt-dlp side.

YT-DLP COMMAND POINTING AT SHARED HISTORY FOLDER: [[Header]]
yt-dlp -x -P "<download folder>" --download-archive "<download folder>/history/downloaded_history.txt" <playlist-url>

2.3.1 PLAYBACK MODES [[Header]]

DIFFERENT PLAYBACK MODES:[[Header]]

There are five different playback modes. In the main UI the small box to the right of the search bar
indicates which playback mode is currently active. Use [m] to step through them.

S[[Header]] ==[[Header]] SHUFFLE MODE[[Header]]
Shuffles through tracks that are currently in the local audio files list (search filters apply!).
Note that you can also actively shuffle to next song in the list via [#].
The QUEUE is never shuffled: [n] and the end of a track play its next title in order; only [#]
picks a random title of the queue.

L[[Header]] ==[[Header]] LIST MODE[[Header]]
Plays the next song in the list (filters apply!).

R[[Header]] ==[[Header]] REPEAT MODE[[Header]]
Repeats the current track again.

O[[Header]] ==[[Header]] STOP MODE[[Header]]
Plays the current song and then stops.

Q[[Header]] ==[[Header]] QUEUE THEN STOP MODE [[Header]]
Plays through the tracks in the queue and then stops.

2.3.2 BUILDING A QUEUE [[Header]]

Tracks can be added to a queue from the local audio files pane.
The order can be adjusted and queues can be saved as playlist. 

GENERAL: [[Header]]
[SHIFT+k]       open the big queue overlay (full size queue list)
                [/] there: search bar at the bottom, matches are marked ([UP/DOWN] jump);
                it searches all tags of the files, also those no screen shows
[SHIFT+l]       open the big list  overlay (full size list)
[SHIFT+UP/DOWN] jump a whole page up/down  (or [PgUp] / [PgDn])

With the LIST focused: [[Header]]
[a]             add track to the TOP of the queue
[e]             add track to the END of the queue

With QUEUE focused: [[Header]]
[d]             remove from queue
[4/5]           move UP / DOWN
[$/%]           move to TOP / END
[a]             does nothing here (it only adds a track from the LIST pane)

QUEUE related commands, no matter the focus: [[Header]]
[!]             lock / unlock (default is locked: move to queue end when played)
[SHIFT+x]       clear it (asks first)
[CTRL+SHIFT+z]  undo the last clear (one level)
[CTRL+SHIFT+u]  queue to a new or an existing playlist (asks first)
[SHIFT+a]       with the LIST focused: add the highlighted track to a new or an existing
                playlist (saved at once, no editor; online tracks are downloaded first)
[SHIFT+g]       bulk add from any pane: paste a YouTube playlist link, queue its tracks
                (a normal text box: caret, marking, copy/paste). It only queues them:
                nothing is downloaded when adding

2.3.3.1[[Header]] META DATA EDITOR[[Header]] —[[Header]] EDIT TAB[[HEADER]]

OPEN AND CHANGE TAB:[[HEADER]] Open via [SHIFT+m] and use [<-/->] to change tabs

NOTE:[[HEADER]] Use [SHIFT+r] to rescan, in case you just recently added new tracks to a
local path folder, otherwise they won't appear in the library list...

LAYOUT AND CHANGING FOCUS BEHAVIOR:[[Header]]
The SEARCH PANE [[HEADER]] uses fuzzy search on files and their meta data, if given. The
LIBRARY PANE [[Header]] only shows the file names. When the focus is on the LIBRARY PANE[[HEADER]] 
and hitting [ENTER] on a highlighted track, the focus moves to the EDIT PANE[[Header]]. Same can be 
achieved via [TAB] which changes the pane focus in general.

EDIT META DATA IN THE EDIT PANE:[[Header]]
Move the cursor to the row you want to change and hit [ENTER] to edit a meta data tag field.

SEARCH PANE:[[Header]] [ESC] clears the search, a second [ESC] closes the editor. Start the search with /f:
(e.g. /f:abbey) to list the tracks of matching folders.

MOVING THROUGH LISTS:[[Header]]
[SHIFT+up/down]  page up / down      [CTRL+up/down]  first / last row
[PgUp] / [PgDn]  the same page keys. Not every keyboard has them without FN and some terminals
                 handle FN keys badly, so [SHIFT+up/down] does the same everywhere.
[ESC] in the LIBRARY PANE first removes an active filter (x/T/A/L/Y), the next [ESC] moves to the search field.

TRACKER FILES AND CHIPTUNES: what the file can hold is written into it (title of .mod .xm .s3m .it; title and
artist of .sid). All other fields are saved in the folder "chip_tracker_meta data" next to the music.

COVER IN THE EDIT PANE AND COVER OPTIONS:[[Header]]
The cover of the highlighted track is shown under the fields. Move down to the button
[ Cover Options ] and hit [ENTER]: choose a picture for THIS track (inside the file, in its
folder, in its fetched_covers folder, the album's covers), "Automatic" (Settings -> Cover
Search decides), "No cover", delete a picture from the disk ([DEL], not the one inside a file)
or search pictures by file name ([TAB] or [/]). The choice goes before the album default of
the cover fetch menu and before the Cover Search setting (except "Within File Only").
Next to it sits the button [ Style Option ] (move there with [->] or [ENTER] on it): a small
overlay with the look of THIS track (as in Settings, Disk, Just Cover, Cover with Gradient, the
Cover behind Disk looks, the ASCII looks), its own Cover Contrast, Cover Brightness and Cover
Colors, and the look of its whole ALBUM (no album tag: of that folder). [<-][->] change a row,
[DEL] or [d] puts it back to "as in Settings". [t] switches between a real picture
(Kitty / Sixel terminals, the default) and braille dots. A wide terminal adds a preview of the cover with the
chosen look on the right. The track's own values win over the album's look and
over Settings; while the track plays, [CTRL+t] / [CTRL+z] change its look.
From the main screen [SHIFT+s] opens the Style Option overlay of the track that plays, on its
own ([ESC] closes it); opened that way [m] leads on to the meta data of that very song.

SORT LIBRARY AND ADD TRACK TO FETCH META DATA TAB:[[Header]]
Several sort options are available for the LIBRARY PANE:

[a]         Add a track to the fetch list
[SHIFT+f]   Add all searched tracks to the fetch list (the result of the search 
            in the library pane; the filtered overall list so to speak)
[f]         Folder view: the pane grouped by folder (a header row per folder, its files numbered
            from 1 below it). On a folder header [a] adds the whole folder to the fetch list and
            [ENTER] closes / opens the folder. [f] again returns to the plain list.
[r]         Show edited tracks first (highlighted in the same color as headers)
[n]         Show recently added tracks first (newest files on top)
            The pane title shows what is active, e.g. [EDITED FIRST + MISSING TITLE].
            After [f], [r], [x], [SHIFT+t/a/l/y] the list jumps to its top.
            [ESC] removes it step by step: first the filter, then [r]/[n], then leaves the pane.
[x]         Show all tracks with NO META DATA
[SHIFT+t]   Show all track with MISSING TITLE tag
[SHIFT+a]   Show all tracks with MISSING ARTIST tag
[SHIFT+y]   Show all tracks with MISSING YEAR tag
[SHIFT+l]   Show all tracks with MISSING ALBUM tag
NOTE: If [r] or [n] shows no titles, one of these filters may still be active - it
hides all tracks that are not missing that tag. The bottom row then says
"NOTE: [MISSING TITLE] filter active, hit [ESC] to clear filter". [ESC] clears it.

FETCHING META DATA OF SINGLE TRACKS[[Header]]
[SHIFT+b]   Fetch missing tags of a SINGLE TRACK (EDIT tab, library list)
[SHIFT+c]   Jump to the song that plays now (search text and filters removed)
[SHIFT+n]   Fetch all tags (again) of a SINGLE TRACK (overwrites existing tags)

GENERAL BEHAVIOR OF META DATA EDITOR:[[Header]]
Every change goes into a pending edit session, autosaved after each keystroke.
Closing the editor, quitting, even a crash keeps it. Edited fields and their
library rows are drawn in the header colour, so you can see what will be written.
Also, when fetching takes a while and you exit the meta data menu, fetching does
not stop, will continue in the background.

2.5.2 OSCILLOSCOPE [[Header]]

THE XY OSCILLOSCOPE: [[Header]]
Like a real scope in X-Y mode. Wide stereo fills the area, a phase-shifted tone draws an ellipse.
A nearly mono track fades over to a phase portrait instead of a flat line.

TUNING OVERLAY:[[Header]] [SHIFT+o] opens it, the picture changes live while the music plays.
[SHIFT+i] / [SHIFT+u] switch straight to the spectrogram options / full screen.
Scope mode       XY, YT, XY + YT (overlap), XY + YT (row), XY + YT (column)
Osci style       braille (works in any terminal) / image (pixels, needs Kitty graphics or Sixel)
Frame rate       30 / 45 / 60 / 90 / 120 / 165 fps
Osci music mode  for oscilloscope music: the unprocessed signal and a fixed scale
Beam             CRT: every sample drawn once, light by the time the beam spends on a spot
                 (image default) / classic: the old look with a tail (braille default)
Dwell brightness CRT beam: slow strokes bright, jumps dark; off = every stroke equally bright
Low-rate blank.  music mode, CRT beam: files below 96 kHz get the jumps between shapes faded out
Rough mode       not in music mode: loud beats clip along the edges of the square (edge clipping;
                 braille default on, image default off); not optimal, technically, but looks cool :D
Image res/detail image style: drawn at full / half / third resolution; detail normal / high =
                 up to 560 / 1024 pixels wide (high: sharper thin lines, more data per frame)
Decay            the afterglow, higher = longer trails
Tail / Glow      bright head with fading tail / line glow
Z-Axis           beam brightness follows speed or level
Color            the VIZ gradient or 8 palettes
Each style keeps its own values, so switching between braille and image never loses your tuning.
[R] resets only the style in use.
Starting points for braille: crisp scope = Decay 0.65, Dot threshold 0.35, Tail 0.60.
Dreamy glow = 0.90, 0.20, 0.25.
Oscilloscope music (e.g. Jerobeam Fenderson): Osci music mode on, Beam CRT, Decay about 0.10,
Image resolution full, Image detail high -- close to osci-render. Lossless files work best.

2.5.3 SPECTROGRAM AND EXTRA WINDOWS [[Header]]

THE SPECTROGRAM: [[Header]]
Made the way Audacity makes its spectrogram view, with Audacity's defaults (2048-sample Hann window,

[SHIFT+o] / [SHIFT+0] in the options: switch straight to the oscilloscope options / full screen
View         spectrogram / WATERFALL: a stack of spectra (newest in front, older ones behind, shifted up and
             to the right), every graph filled with the colors and outlined in black. Own rows: Graphs,
             Graph spacing, Slant, Peak height, Resolution (high = twice as fine, scaled down) (braille: lines of dots; full screen: frequencies on the top ruler)
Scale        linear / logarithmic / mel / bark / erb / period
Motion       sweep (a page at a time) / scroll (newest on the right)
Window size  256 .. 8192: bigger = sharper frequency lines, smaller = crisper clicks and drum hits
Time span    5 .. 60 s across the width
Colors       roseus / classic / grayscale / your VIZ gradient

[)]   scope window            German keyboard SHIFT+9, English keyboard SHIFT+0
[(]   spectrogram window      German keyboard SHIFT+8, English keyboard SHIFT+9

2.6.2 LOUDNESS NORMALIZATION AND STEREO/MONO [[Header]]

LOUDNESS NORMALIZATION: [[Header]]
Plays every track at the same perceived loudness, so a quiet album does not disappear after a loud one.
[v]        on / off, without opening anything
[SHIFT+v]  the overlay: on/off, target level, max boost

Normalize     off / on                      (default on)
Target level  -40 .. 0 LUFS                 (default -16)
Max boost     0 .. 24 dB                    (default 9)

-16 LUFS leaves headroom, -14 matches YouTube and Spotify. The grey live line under the rows shows
the measured loudness of the playing track and the gain actually applied, so you can see at once
when Max boost is holding a quiet track back. In the radio a stream has no end, so the loudness is
measured since you tuned in and the gain glides in over a second.

STEREO OR MONO: [[Header]]
Settings ->> GENERAL ->> Stereo Sound. Off folds left and right together (and halves the memory a
loaded track needs). Turning it off is immediate; turning it on applies from the next track.
In the radio the footer of the dial then reads MONO.

[[New Page]]
2.6.3 SAMPLE RATE AND PLAYBACK ENGINE [[Header]]

SAMPLE RATE: NOTHING IS CONVERTED ON THE WAY: [[Header]]
Every file plays at its own sample rate (44.1, 48, 88.2, 96 kHz ...): it is decoded at that rate and
the audio device is opened with it. Above 96 kHz the track is brought down to 96 kHz, unless
Settings -> GENERAL -> Rate Cap at 96 kHz is switched off (then it plays at its own rate and
needs more memory). Where a
conversion cannot be avoided a long, sharp filter is used, not a cheap linear one.

LONG TRACKS NEED LITTLE MEMORY: [[Header]]
A short track is decoded completely into memory. A long mix is only decoded in a 2-minute window
around the position (90 s ahead, the last 30 s kept, so a short step back is instant).
A 200 MB file takes about 50 MB instead of gigabytes. The audio is exactly the same: same rate,
same 32-bit samples.

THE ORDER THINGS HAPPEN IN: [[Header]]
decoded audio  >  equalizer  >  normalization  >  limiter  >  volume
The scopes can tap the signal before all of it when the Osci music mode in the [SHIFT+o] overlay
is turned on. The spectrogram always decodes before all of the above. The spectrum bar and
the sphere use the (mono) mix of a track so they use the end signal of the above (after volume).

3.3.1 TIMESHIFT [[Header]]

From the moment you tune a station the radio keeps the last minutes of it in a rolling buffer on
disk, so live radio can be treated like a recording.

KEYS: [[Header]]
[SPACE]   pause. The station keeps arriving in the buffer; [SPACE] again resumes where you stopped
the square bracket keys (left / right)   back / forward 30 seconds
                                         (German keyboard: [ALT GR+8] / [ALT GR+9])
the curly bracket keys (left / right)    back 5 minutes / back to live
                                         (German keyboard: [ALT GR+7] / [ALT GR+0])
Every jump is shown for 4 seconds under the scope block, e.g. -0:30 | 2:30 behind live.
You can never go back before the moment you tuned in: internet radio only delivers from "now".
Catching up with the forward key hands back to the live stream without a gap. Tuning another
station, [x] or quitting clears the buffer.

THE BUFFER: [[Header]]
The size is [s] Settings[[Header]] ->> GENERAL[[Header]] ->> Timeshift buffer (5, 15, 30, 45 or 60 minutes,
default 30). The file is radio_timeshift.pcm in ~/.cache/mousiki/ and takes about 11.5 MB per minute
(about 345 MB for 30 minutes). It is written by the stream thread and never touched by the screen
loop, so the interface stays as fast as without it. It is deleted when the radio closes.
If a pause lasts longer than the buffer, the oldest part is overwritten and playback continues
from the oldest audio that is still there.

RECORD, INCLUDING THE MINUTES BEFORE YOU PRESSED: [[Header]]
[y] opens the RECORD overlay. It freezes the moment you pressed, so no time is lost while you choose:
-> From now on (when this opened)
-> The last 1 / 5 / 10 / 15 / 30 minutes

A row says "only m:ss" when the buffer does not reach that far back and then starts at the oldest audio.

While it runs the footer of the dial shows REC mm:ss.

WHAT YOU GET: [[Header]]
The recording is written from the buffer as a WAV, which ffmpeg then converts in the background to

volume, mute and the mono fold.

Into the download folder of the radio ([s] Settings[[Header]] ->> PATHS[[Header]]), which by default is
the one of the music player. After a rescan ([SHIFT+r] in the player) the recordings are part of
your local library.

3.3.3 RADIO HISTORY [[Header]]

THE RADIO'S OWN HISTORY: [[Header]]
[h] opens it; [ESC], [q] or [h] close it. [1] [2] [3], [<-/->] or [TAB] switch the tab, [UP]/[DOWN]
move, [HOME]/[END] jump to the ends.
[1] HISTORY        WHEN / CHANNEL / ARTIST / TITLE / HEARD
[2] TOP CHANNELS   channels by time listened ([r] flips the order)
[3] HABITS         sessions, time per day, channels, and listening by hour and by weekday
A new HISTORY line starts whenever the channel, the artist or the title changes. Lines heard for less
than 3 seconds are dropped. A session ends after a gap of 30 minutes. The newest 10 000 lines are
kept one by one; older ones are folded into lifetime totals, so TOP CHANNELS and HABITS stay lifetime
figures.

The radio writes down the artist and title the stream sends. On the HISTORY tab [y] on a line opens an
overlay that searches YouTube for "artist title". [ENTER] downloads the hovered result into the
download folder (yt-dlp, opus), [TAB] edits the search query, [ESC] closes. A result is marked
[ok] done, [..] downloading, [!!] failed.
This is the online search of the music player reached from the radio, so a song you only heard once
on air ends up in your local library (after a rescan with [SHIFT+r] in the player).

[TAB] next tab, [UP]/[DOWN] rows, [<-/->] or [ENTER] change a value, [s] saves and closes,
[ESC] / [q] discards (asks first when something changed).

The settings are stored in radio_config.txt, separate from the config.txt of the player. 
Colors are not carried over between the two modes: the radio has its own palette and its 
own theme choice, unless the option "Shared profile" is set to true.

COLORS (ONLY THE RADIO HAS): [[Header]]
ON_AIR            the diagonal gradient of the ON AIR sign, the needle, the lamp and LIVE
OSCI              left / right color of the oscilloscope
FREQUENCY_BAR     the line and ticks of the dial / the numbers and dots
VOLUME            current / possible part of the volume bar
PRESETS           inactive slots (FG/BG) and the shortcut letters
BORDER_COLOR, METADATA, VIZ, LIST, HEADER, LEGEND and TAB_NAMES work as in the player, and so do the
THEME row, [e], [SHIFT+d] and the unsaved-changes questions.

GENERAL: [[Header]]
Playback (shuffle / list, like [m]), Start Mode (player / radio / audiobook), Use Music Player / Use Radio /
Use Audio Books and Mode Order 1..3 (the same rows and values as in the player, kept in its config.txt),
Black Background, On air ascii,
Pulse wave, Dummy buttons, Volume indicator (the look of the VOLUME BAR, like in the player),
Spectrum Bars, Stereo sound, Normalize volume, Tuning noise (static while
tuning, off by default and never recorded), Timeshift buffer (5 / 15 / 30 / 45 / 60 minutes),
Use oscilloscope / Use spectrogram.

ANIMA/VIZ: [[Header]]
Gradient wave speed and Pulse wave speed (the ON AIR sign), Bars Style with the Hi-Fi rows, Bars Behavior,
Bars Fluidity / Degradation / Viscosity,
Osci/sphere (osci / sphere / spectro / off) and Osci style (braille / image).

3.4.2 RADIO SETTINGS: PATHS, KEYS AND FILES [[Header]]

PATHS: [[Header]]
Every path is a base folder; the radio makes its own sub folders below it:
STATION LISTS PATH   stations/ and station_lists/          PRESETS PATH   presets/presets.txt
DOWNLOAD PATH        radio_downloads/ (or the same folder as the music player)
HISTORY PATH         radio_history/
AUDIO BOOK PATH      the player's audio book folder (kept in the player's config.txt, listed here 
                     so it can be set from every mode)
Changed folders are copied, never moved, and nothing is deleted. Playback stops and everything reloads.

REFERENCE: REBINDING THE KEYS OF THE RADIO: [[Header]]
The keys that are not hard coded, grouped like the player's: PLAYBACK, MENUS, TIMESHIFT and SYSTEM.
[ENTER]  on a row, then type one character (case matters) or SPACE / TAB / BACKSPACE
[DEL]    restore the default of that key
[CTRL+SHIFT+u]  undo the last five key changes
The first row, Reset all keys to default, sits under the cheat sheet note at the top.
A key that is already in use is refused, and the fixed keys count too: the 16 preset keys (1..0 and
e r t d f g) and the vi-style [j] / [k]. The cheat sheet [?] always lists the default keys.

THE FILES OF THE RADIO: [[Header]]
radio_config.txt   settings, colors, equalizer, oscilloscope (keys as HKey<Action>= lines)
stations.txt       your station list                    presets.txt       the presets and the active one
stationlists.txt   the saved station lists              preset_names.txt  the short names of the PRESETS pane
radio_history/     history_radio.txt and archive_radio.txt
All of them live in the config folder: ~/.config/mousiki/ (Windows: %USERPROFILE%\.config\mousiki\).

AUDIO BOOK MODE: [[Header]]

The audio book player is the third mode of Mousiki Plus and represents the music player 
shaped for listening to books. 

[SHIFT and +] (German keyboard) / ['] (English keyboard) go to the next mode,
[SHIFT and -] (German) / [;] (English) back to the previous one. By default the order is
music player, radio, audio books; Settings -> GENERAL -> MODES switches modes off and changes the order.

LIKE THE RADIO, IT IS ANOTHER PLAYER INSIDE THE PROGRAM: [[Header]] when you leave it, the
chapter that plays is paused and everything stays as it was.

SETTING IT UP: [[Header]] 
Settings -> PATHS -> AUDIO BOOK PATH takes ONE folder (also listed in the radio's
settings). Every folder in it that directly holds audio files is one book; the files in it are its
chapters. A .cue file next to each book files records where you last stopped listening.
The books pane walks through the folders like a tree: a folder that holds other books shows as 
[> Name  n books], ENTER goes into it (its own audio files come first, then the folders below), 
the first row [<- ..] ENTER goes back up or hitting [ESC]. A search shows all books flat.


[[New Page]]
4.1.1 THE AUDIO BOOK SCREEN AND ITS KEYS [[Header]]

PANES: [[Header]]
BOOKS (left)      only folders: one row per book with its number of chapters. [ENTER] opens the book.
                  [/] searches the books, [ESC] shows all books again; in the chapter pane [ESC] goes 
                  back to the library pane; in a folder of the library pane [<-] and [ESC] go one step 
                  up in the folder hierarchy.
CHAPTERS (right)  takes the place of the queue: the files of the open book in natural order
                  ("Chapter 2" before "Chapter 10"). [ENTER] plays a chapter. [TAB] moves the focus.
                  Hitting [ESC] moves back to the library/books pane. 

PLAYBACK: [[Header]]
[n] / [b]    next / previous chapter, also at the end of a chapter. 
[m]          cycles the playpack mode: on to the next chapter / repeat the chapter / stop after it. 
[->] / [<-]  seek: 5 seconds at first, faster and faster the longer the key is held (up to minutes), 
             so a long book can be crossed quickly. [p] pause, volume, mute and the sleep timer as always.

PLAYBACK SPEED: [[Header]]
[SHIFT+->] / [SHIFT+<-]  faster / slower in steps of 0.05, from 0.5x to 3.0x. The voice keeps its pitch
             (the audio is stretched in time, not played faster like a record). A small box left of the
             play mode box (right of the search bar) shows it: 1.0x, 1.25x ... It is as wide as its text.
             The speed is saved at once and is also in Settings, GENERAL, AUDIO (Playback Speed).
             Times, bookmarks, notes and the progress bar stay in the time of the book: at 1.5x a 60
             minute chapter still shows 60:00, it just takes 40 minutes. The music player and the
             radio always play at 1.0x. 

THE DEFAULT PICTURE: [[Header]] 
An image of a women rading a book (a grey version of a colour picture) takes the place of the disk. 
It is drawn as small braille dots (a 60 x 60 dot field) and stays still; the colour wave of the 
radio's ON AIR sign runs over it diagonally, from the upper left to the lower right. In a terminal 
with Kitty graphics or Sixel (Windows Terminal 1.22+, Kitty, WezTerm ...) it is a real transparent 
image at full pixel resolution instead of braille dots (a terminal without them gets the braille 
version, which does not look nice though, to be honest). The original of the beautiful default 
image is done by Kamara Rahmat (iyaniyan; taken from Unsplash).

BOOK COVER: [[Header]]
The option [Book Cover] in Settings, GENERAL, set to true shows the cover image found in the book's 
folder instead (a file named cover, folder, front or albumart, else the first picture there; 
jpg, png, webp ...; no picture file: the cover art inside the first audio file is used). The 
gradient wave can also be toggled via [Book gradient]. With the wave on, [Cover Brightness]
(50% = as it is) and [Cover Colors] (how much of the cover's own colours shines through the
gradient) work on the book's cover too (Settings, ANIMA/VIZ, BOOK COVER).

A book without a cover image keeps the default picture. Switching Book Cover on shows in the 
status line which protocol is used and the cover file found (or why there is none; the console log, t, 
has the path). Where the visualizations are, a stack of books builds itself up while no book is loaded.

META DATA: [[Header]] 
Given are book, author, narrator, chapter (number and title), publisher, genre, the length 
of the book and how much of it has been heard, then sampling, format and file size.

MENUS FROM OTHER MODES: [[Header]] 
The converter [SHIFT+c] works on the audio books and searches folders with [/f:]. The equalizer
[SHIFT+e] and sleept timer [SHIFT+z] is also available in this mode.

4.1.2 BOOK TAGS [[Header]]

[SHIFT+m] opens the tag editor of the audio book player. It only edits, nothing is fetched in this
mode, which makes the meta data editor much more light weight and simple. 
It shows one chapter at a time: 
File name, Book title, Author, Narrator, Chapter, Publisher, Year and Genre.

[UP]/[DOWN]   pick a row, [ENTER] types into it (a second [ENTER] puts the cursor away), 
[<-]/[->]     go to the other chapters (unsaved changes have to be saved with [s] or dropped 
              with [d] first). A changed row is drawn in the header colour) 
[s]           writes this chapter's changes. The audio is copied bit for bit (ffmpeg -c copy). 
              The File name row edits the name only; the ending (.mp3 ...) stays.
[a]           writes the changed book rows (book title, author, narrator, publisher + year, genre) 
              to every chapter of the book; the chapter title stays each chapter's own. The chapter 
              number always goes in FRONT of the name (01 Dune, 02 Dune ...): the folder is sorted 
              by name, so the number keeps the track order whatever the titles are.

A number that is there already is not added twice; numbers at the END of every name (Dune 01) are moved 
to the front of every file - the editor says why and asks [y] / [n] first. [s] puts the number in front 
of the renamed chapter.Bookmarks, auto-mark, chapter marks and notes follow the new file names. 
[ESC] leaves; with unsaved changes it asks: [y] save, [n] discard, [ESC] keep editing.
Publisher and year are one row: "Penguin, 2019" (a last part with four digits is the year).
The narrator is stored as composer and narrator tag, the book title as album, the author as artist. Narrator,
publisher and year are also written to the book's .cue file (REM NARRATOR / PUBLISHER / DATE) and read from it first, so a WAV file keeps them too.

4.1.3 BOOKMARKS AND NOTES [[Header]]

THREE KINDS OF TIME STAMPS: [[Header]]
AUTO-MARK  where you stopped; written by itself every few seconds while you listen and when you leave
           (.cue: REM AUTOMARK). One per book.
BOOKMARK   a place you set on purpose with [SHIFT+b]; a book and even a chapter may carry many. They are
           numbered automatically: Bookmark 1, Bookmark 2 ... (.cue: REM BOOKMARK).
NOTE       a bookmark with a text (SHIFT+n, below); without a title it is numbered: Note 1, Note 2 ...

The chapter with the newest bookmark is lit in the header colour with a diamond.
[d] in the chapter pane deletes the bookmark of the chosen chapter (a small question first).
Before the chapter changes ([n], [b], [ENTER] on another one), the mode switches or Mousiki quits, a
question asks "Set a bookmark here?" with the exact time: [y]/[ENTER] yes, [n] no, [ESC] stay.
The audio is paused while the question is open. Settings -> GENERAL -> BOOKMARKS -> Ask for Bookmark 
turns it off, since it can become annoying and auto-mark is always on anyways.

[ENTER] on a chapter that was left but not bookmarked asks "Do you want to continue where you left?":
  [y] Continue there (the only answer that starts the chapter)   
  [n] Leave, keep the auto-mark, nothing is played
  [b] Convert auto-mark to bookmark and leave (nothing is played)   [ESC] cancel.

[ENTER] on a chapter with ONE bookmark offers: on the spot / 10 / 20 / 30 / 60 seconds before / the start
([UP]/[DOWN] + [ENTER] or [1] to [6]; [ESC] does not play it).

[ENTER] on a chapter with SEVERAL time stamps lists them: Auto-mark, Bookmark 1, 2 ..., the notes by title,
and the start of the chapter; the choice opens the resume offer.

[CTRL+SHIFT+u] brings back the last deleted time stamp (up to 30).

NOTES: [[Header]]
[SHIFT+n]  a note at the time you pressed [SHIFT+n] (not when you save): the field of the visualizations 
           becomes the editor. First line = title, [ENTER] goes on to the text. [CTRL+SHIFT+s] saves; 
           [ESC] stops typing, then [SHIFT+s] saves, [ENTER] types on, [ESC] again discards. 
           The audio goes on while writing a note and the note is shown in the future when the respective 
           time stamp is passed.
           [CTRL+n] goes on in the big notes overlay (same text, same caret), there [CTRL+n] comes back.
           A shown note: [CTRL+n] opens it there for editing. The time stamp (@ h:mm:ss) always stays whole.
[SHIFT+l]  all notes in a full-screen overlay: the list left (chapter, time, title), the note right.
           [ENTER] (or [t]) edits it right there, [f] shows it in the field, [SHIFT+p] plays from that 
           point (the note is in the field after the overlay is closed), the right pane becomes the editor, 
           [n] writes a new note at the playing point, [x] deletes, [SHIFT+e] / [SHIFT+i] export / import (an
           import adds only new notes).
[SHIFT+t]  sorts: chapter order with highest chapter and furthest time on top, recently edited first.
[.] / [,]  switch the field between the notes and the visualizations. When a note is open and was just
           saved [.] puts a shown note away: the view from before comes back. [,] on a shown note (e.g. 
           right after saving it) writes it again.

Export / import of notes is possible and use the folder <book folder>/notes.
Again, a note shows itself in the field (for 20 seconds) when playback passes its time.

4.1.4 LIST OF TIME STAMPS, LIBRARY AND READING HISTORY [[Header]]

A book has an auto-mark, any number of bookmarks and notes. Three big windows:

LIST OF TIME STAMPS [SHIFT+k]: [[Header]] 
It shows every auto-mark, bookmark and note with the columns: when, TYPE (Auto-mark, Bookmark or Note), 
book, chapter, time; the newest first, notes last. 
[UP]/[DOWN] choose, [SHIFT+UP]/[SHIFT+DOWN] page.
[ENTER]    opens the book, goes to the chapter and offers the resume choices 
           (on the spot / 10 / 20 / 30 / 60 s before / start).
[SHIFT+p]  opens the book and plays from the time stamp at once; the list stays.
[SHIFT+d]  discards a time stamp of any kind - a warning asks first; [y] confirms this step.
[SHIFT+b]  turns an auto-mark into a regular bookmark.
[SHIFT+t]  sorting: by the date the stamp was set (newest first), by book (A-Z, the highest chapter 
           and the furthest mark first).
[ESC]      back to the date sorting, and closes.
[CTRL+SHIFT+u] brings the last discarded one back.
[ESC]      closes/clears sorting.

BIG LIBRARY OVERLAY [SHIFT+s]: [[Header]] 
It has a search pane on top ([/] types, the words narrow the list) and the audio book pane below it.
[ENTER] / [->] on a book opens it and inserts its chapters below it, [<-] or [ESC] closes it; 
               a diamond marks a bookmark.
[ENTER]        on a chapter plays it (the bookmark question first), [CTRL+p] plays it from its start 
               and the overlay stays,
[f]            opens the book in the chapter pane.

LISTENING/READING HISTORY [SHIFT+h]: [[Header]] 
The listening history made for books, in its own file reading_history.json. Every chapter
you listen to is recorded. Change tab via  [<-]/[->] or [1] to [4]. 
Given tabs are HISTORY, TOP CHAPTERS, TOP BOOKS, HABITS.
[ENTER] on a chapter opens its book and plays it. [ESC] closes.

4.1.5 CHAPTER MARKS AND CUTTING [[Header]]

A book is sometimes one long file. [ALT+l] (macOS: [SHIFT+j]) opens the chapter marks of the chapter
that plays (else the chapter under the cursor starts). The window shows where you are and the marks: number, time, 
title, length. You set them while listening:
[m]        a mark at the point you listen at. The first mark adds the start (0:00:00, "Chapter 1"). 
           A new mark is called "Chapter N" (the standard titles are renumbered when one is inserted); 
           the title field opens with it selected:[ENTER] keeps it, typing replaces it.
[a]        a mark by its time, h:mm:ss (or m:ss), then the title.        
[t] / [r]  change the time / the title.
[x]        deletes the mark.                                              
[ENTER]    plays from the mark.
[<-]/[->]  seek: 5 seconds, faster and faster the longer the key is held, up to minutes. [p] pauses.

The marks are saved in the book's .cue after every change (REM CHAPTER lines).

[c] CUTS THE FILE: [[Header]] 
after one question ffmpeg copies the parts without re-encoding (-c copy) into the book folder 
as "01 Chapter 1.wav", "02 The Storm.wav" ... with the chapter title as title tag. If anything 
fails, the new files are removed and the original is untouched. Answer the question with [t] 
instead of [y] to also trim blank audio at the edges of the parts to 2 seconds (bookmarks, 
auto-mark and notes are moved accordingly).

THE BACKUP: [[Header]] 
The original becomes "Dune.wav.mousiki-backup" in the book folder (not listed as a chapter) and 
stays until you delete it on purpose: [SHIFT+d] in this window shows how much space it takes...

BOOKMARK AND NOTES FOLLOW: [[Header]] 
The bookmark and every note in the cut file move to the part that holds their place,
with the time inside that part (a note at 0:25:00, a chapter starting at 0:10:00: 0:15:00 
of the new chapter).

5.1.1 REMOTE CONTROL AND KEY BINDINGS [[Header]]

A running player or radio can be controlled with the same program:
  mousiki --cmd next | prev | play-pause | pause | stop | shuffle | mute | live  
                     | playback-mode | wizard | switch-mode | quit
  mousiki --cmd volume 60    mousiki --cmd volume-up    mousiki --cmd seek -30

  mousiki --status           Shows what is playing right now...
  mousiki --cmd --help       Shows every command...

Windows, Linux (MPRIS) and macOS (Now Playing): the system media keys and widgets already control Mousiki.
No media keys on your keyboard? Bind ANY key combination in your system to such a line:

GNOME/KDE: custom shortcut with the command   mousiki --cmd next
i3/sway:   bindsym Ctrl+Mod1+Right exec mousiki --cmd next
Windows:   AutoHotkey   ^!Right::Run "mousiki.exe" --cmd next, , Hide
macOS:     Shortcuts app (Run Shell Script) or skhd

5.1.2 THE REMOTE APP (PHONE) [[Header]]

Settings -> GENERAL -> REMOTE / UPDATES -> Remote App -> [ENTER] opens the REMOTE APP overlay (player or radio):
switch it ON, see the address and a QR code (scan it with the phone camera: the remote opens,
logged in), change the PORT or the PIN ([n] a new one). [ESC] back, [s] saves the settings.
Works with your own build as well as with an installed Mousiki. The phone must be in the same network.

ANDROID APP: [[Header]] Mousiki Remote (remote_app/android): enter the address and the PIN once,
or let it find Mousiki in the network.

PHONE BROWSER: [[Header]] open the address and enter the PIN.
The phone shows the disk, the meta data, the progress bar, the dummy buttons (working: seek,
play/pause) and boxes for prev, random, next, volume, mute, playback mode, LISTS and manual --
drawn by Mousiki in the colours of your theme. In the radio: the ON AIR sign, the station,
prev/next station, pause, live, stop.

LISTS (player): on top the local list (tap a title: it plays), below the saved playlists (tap one: its titles
go into the queue, starts it when nothing plays). A tap on the other list gives it the focus; UP / DOWN
move the list in focus a whole page. CLEAR QUEUE at the bottom: tap twice.

STATIONS (radio): the whole station list, tap a station to tune it. UP / DOWN page, BACK returns.
[RADIO]/[PLAYER] at the top switches the mode.
Long press on the phone: its own settings (base colours, size of the braille dots, PIN).

NO CONNECTION? [[Header]] same Wi-Fi? A VPN blocks the home network unless "local network access" is allowed in it.
Windows: [f] in the overlay opens the port in the firewall. Test: http://127.0.0.1:4747 on the computer.
SAFE: [[Header]] off by default, home network only (other addresses are turned away), PIN for every
command, 10 wrong PINs lock that one device out for a minute (not your phone). Plain HTTP: use it on
a network you trust. Windows asks once whether Mousiki may accept connections: allow private networks.
